# 珀莱雅官旗商品汰换决策分析

面向即时零售商品经营的个人数据分析作品集。项目先通过可复用的商品汰换数据清洗Skill建立门店×SKU标准底表，再使用同品类Min-Max风险标准化、加权评分与业务保护规则，形成“保留—引流/观察—汰换候选”三档决策。

[在线作品集](https://charlie060302.github.io/proya-product-retirement-dashboard/) · [直接打开看板](https://charlie060302.github.io/proya-product-retirement-dashboard/dashboard.html) · [简历文案](docs/RESUME.md) · [方法说明](docs/METHODOLOGY.md)

## 项目职责

- 独立完成业务问题梳理、数据口径设计、商品评分模型与分析验证。
- 搭建商品汰换数据清洗Skill，自动识别五类输入，完成门店与SKU匹配、城市映射、库存冲突保护、销售聚合、品类补齐及输出校验。
- 设计同品类风险指数、双低门槛及新品/小样本/高贡献保护规则。
- 借助AI从0到1开发原生HTML交互看板，并完成筛选、下钻与导出功能。

## 分析结果

真实项目样本原表5,747行，经字段校验后纳入4,211条有效门店×SKU记录，覆盖142家门店、122个SKU与14个品类。

| 判定 | SKU数 | 解释 |
| --- | ---: | --- |
| 汰换候选 | 12 | 占SKU总数9.8% |
| 引流/观察 | 57 | 单项短板、极低动销或受保护商品 |
| 保留 | 53 | 未触发观察或汰换门槛 |

12个候选贡献2.8%的销售额和1.7%的毛利额，占用4.1%的库存金额，候选库存金额约1.82万元。上述数字是分析输出，用于确定业务复核优先级，不表示库存已经处置或资金已经释放。

## 数据清洗Skill

Skill在本地自动识别商品汰换基表、近期订单、门店—城市映射、门店商品库存、期间销售汇总及可选SKU剔除清单，不依赖固定文件名。

- 以“标准化门店名称 + SKU”为正式记录主键，SKU始终按文本标识符处理；
- 同一门店与SKU存在多条订单时，使用最新订单行的商品名称、店内分类和售价；
- 库存只接受唯一匹配或完全一致的重复值，冲突时保持空值并报告，不随意求和；
- 销量、销售额与毛利额按门店+SKU求和，毛利率重新按“毛利额÷销售额”计算；
- 品类优先按同一SKU的有效众数补齐，再使用完全相同商品名称匹配，无法补齐时停止交付；
- 始终输出新工作簿，不覆盖源文件，并检查指定SKU残留、空品类、隐藏行、筛选范围和公式错误。

## 决策模型

```text
汰换指数 = 35% × 低毛利率风险
         + 25% × 低销售额风险
         + 25% × 低销量风险
         + 15% × 高库存金额风险
```

四项指标在同品类内做0—1 Min-Max风险标准化，最终映射为0—100分。只有“销量和毛利率同时低于同类中位数、指数≥70、没有触发保护规则”的SKU才进入汰换候选。指数≥50或极低动销商品进入观察。

## 数据与证据边界

- 所有历史上传Excel及后续源工作簿均为本地只读输入，不进入公开仓库。
- 真实商品编码、真实门店名称、逐行销售和库存明细均不公开。
- 公开看板默认加载20个模拟SKU、4家“示例门店”，商品编码统一以`DEMO-`开头，只用于展示分析流程与交互能力。
- 仓库忽略`.xlsx/.xls/.csv/.tsv`，自动测试同时检查公开目录不存在业务表格或15—22位真实SKU格式。
- 动销率要求有效销量与库存量记录覆盖率达到80%；覆盖不足时只显示参考值。
- Min-Max受极端值影响，指数用于相对排序，不是因果预测或自动下架指令。
- 新品、套装、战略品、活动品及小样本品类需要人工复核。
