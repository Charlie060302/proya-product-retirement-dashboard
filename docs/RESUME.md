# 简历项目经历

**珀莱雅官旗商品汰换决策分析｜独立分析、AI辅助前端开发**

- **数据工程：**搭建可复用商品汰换数据清洗Skill，自动识别基表、订单、门店城市、库存与销售汇总，以“标准化门店名称+SKU”为主键，完成库存冲突保护、销售聚合、品类补齐及隐藏行/筛选/公式校验；全程只读源文件并输出新工作簿。
- **业务分析：**针对官旗即时零售自产自销试点中运营成本偏高、SKU效率不清的问题，离线清洗并聚合4,211条有效门店×SKU记录，覆盖142家门店、122个SKU；搭建品类、商品筛选及门店销量贡献下钻，定位低效商品与库存占用。
- **模型设计：**构建同品类Min-Max汰换指数，按毛利率、销售额、销量、库存金额设置35%/25%/25%/15%权重；叠加同类中位数双低门槛、新品/小样本/高贡献保护与库存覆盖率校验，降低单一指标和极端值误判。
- **分析结果：**识别12个汰换候选、57个引流/观察商品；候选占SKU总数9.8%，仅贡献2.8%销售额和1.7%毛利额，占用约1.82万元库存，为SKU精简、调拨和库存处置提供优先级。
- **看板交付：**借助AI从0到1开发原生HTML/CSS/JavaScript交互看板，实现销量×毛利率气泡定位、风险原因拆解、商品/品类筛选、门店下钻和候选清单Excel导出。

交互作品：[珀莱雅官旗商品汰换决策看板](https://charlie060302.github.io/proya-product-retirement-dashboard/) ｜ [GitHub源码](https://github.com/Charlie060302/proya-product-retirement-dashboard)

## 使用说明

候选库存金额是待复核的库存占用，不能写成已释放资金或已实现经营收益。公开看板仅使用20个模拟SKU和4家示例门店；历史上传Excel、真实SKU、真实门店和逐行经营明细均不进入GitHub。真实分析结果只以不可还原实体的脱敏汇总呈现。
